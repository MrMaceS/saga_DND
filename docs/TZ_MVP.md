# ТЗ: MVP «Сага Мьёльнира»

Игровые правила: `GAME_DESIGN.md`. Данные: `data/`. Правила уже реализованы эталонно в `engine/rules.py` и покрыты тестами, их менять только вместе с тестами.

## 1. Объём MVP

**Входит:** стартовое меню, создание и вход по коду, лобби, выбор из 11 героев, настройки вечера с голосованием, клятва, экран Стола и экран телефона, раунды с «Закончить ход», сцена «Корабль без команды» целиком (карта, туман, часы, задачи, ИИ-союзник), интерпретатор и диктор через Gemini с запасным режимом, броски, ранения, лечение, «при смерти», бой кнопками, допрос кнопками, общая и личная карты, кат-сцены (озвучка и субтитры из файлов), автосохранение и загрузка, Docker, тесты.

**Не входит (после MVP):** остальные четыре истории, рост между вечерами в интерфейсе (данные есть), живая генерация картинок или озвучки, улучшения из `GAME_DESIGN.md` раздел 16, аккаунты, интернет-режим.

## 2. Стек и архитектура

- **Backend:** Python 3.12, FastAPI, WebSocket, SQLite (`aiosqlite` или SQLAlchemy 2), Pydantic v2, один процесс asyncio.
- **ИИ:** Gemini API (`google-genai`), две роли: интерпретатор (Flash-класса, температура 0, structured output), диктор (сильнее, температура 0.8–1.0). Модели и таймауты в `.env`.
- **Frontend:** Vite + TypeScript, Svelte (или React, если привычнее), SVG для карт, без игровых движков. Два приложения в одном проекте: `/table` и `/hand`. Вся логика и скрытые данные на сервере, клиент только отображает то, что прислал сервер.
- **Деплой:** `docker compose up` (один сервис `app`, опционально `ollama`). Запуск без Docker: `uvicorn app.main:app --host 0.0.0.0 --port 8000`. Порт 8000 открыть в файрволе, показать хосту локальный IP.

```
saga/
  app/
    main.py                # создание FastAPI, роуты, раздача статики
    config.py              # настройки из .env
    api/                   # REST: sessions, heroes, saves, stories, dev
    ws/                    # хаб соединений, каналы table/hand, события
    engine/                # ЧИСТАЯ логика без ввода-вывода
      rules.py             # (готово) проверки, раны, часы, голосования, знания
      dice.py              # RNG с подменой для тестов
      round.py             # конечный автомат раунда
      scene.py             # загрузка сценария, состояние сцены, задачи, часы
      combat.py            # меню боя, реакции, местность
      interrogation.py
      knowledge.py         # факты, known_by, фильтрация, передача
      map_state.py         # состояния локаций, личная карта
      saves.py             # снимок, журнал, восстановление
    ai/
      client.py            # Gemini, таймауты, повторы
      interpreter.py       # сбор контекста, вызов, валидация
      narrator.py
      schemas.py           # Pydantic-схемы ответов ИИ
      fallback.py          # шаблонные тексты
    db/                    # схема (data/schema.sql), репозитории
  web/                     # фронтенд (table/, hand/)
  data/                    # heroes.json, scenarios/*.yaml, fallback_narration/
  assets/                  # картинки, аудио
  prompts/                 # системные промпты
  tests/
  docker-compose.yml, Dockerfile, .env.example
```

**Принципы:**
1. `engine/` без ввода-вывода: время, случайность и ИИ передаются снаружи.
2. Сервер единственный источник правды. Клиент не получает ничего, чего не знает его герой.
3. Любое решение (исход, сложность, ранение, часы, число врагов) принимает движок, ИИ только понимает и описывает.
4. Каждый рассылаемый факт и каждое изменение состояния пишутся в журнал событий (`story_event`).

## 3. Состояния

**Сессия:** `lobby → hero_select → oath → playing → paused → finished`. Пауза возникает при пропаже сервера или при «Сохранить и выйти».

**Раунд:** `declaring → resolving → narrating → saved`. В `declaring` игроки подают заявки и жмут «Закончить ход» (можно отжать). Когда `rules.all_ready` истинно, переход в `resolving`. Сохранение запрещено в `resolving` и `narrating`.

**Порядок разрешения:** (1) перемещения между локациями, (2) Местность, Приёмы, Атаки, Прикрыть (в бою) либо проверки исследования, (3) удары врагов с запросами реакций, (4) тик часов, (5) раскрытие знаний и кат-сцены, (6) вызов диктора, (7) рассылка, (8) автосохранение.

**Кубики бросает сервер.** Игрок нажимает кнопку «Бросить», клиент проигрывает анимацию, результат уже определён сервером (`dice.py` с подменяемым RNG).

## 4. REST API

| Метод и путь | Назначение |
|---|---|
| `GET /api/stories` | список историй (id, название, жанр, диапазоны игроков) |
| `POST /api/sessions` | создать сагу: `{name, story_id, player_count}` (имя 3–60 символов), ответ: `session_id, join_code, table_token` |
| `GET /api/sessions/{code}` | публичное состояние лобби |
| `POST /api/sessions/{code}/join` | `{player_name}` → `device_token` |
| `GET /api/heroes` | каталог из `heroes.json` (без чужих тайн) |
| `POST /api/sessions/{code}/claim` | занять героя (атомарно, один герой одному игроку) |
| `POST /api/sessions/{code}/ready` | готов / не готов |
| `GET /api/saves`, `POST /api/saves/load`, `POST /api/saves/export`, `POST /api/saves/import` | сохранения (только со Стола) |
| `GET /api/assets/manifest` | список ассетов и запасных значков |
| `POST /api/dev/dice` | только при `DEV=1`: задать значения кубика для тестов |

Все ответы с ошибками: `{"error": {"code": "...", "message": "..."}}`. Коды: `session_full`, `hero_taken`, `lobby_closed`, `invalid_state`, `not_your_turn`, `forbidden`.

## 5. WebSocket

Два канала: `/ws/table/{code}?token=<table_token>` и `/ws/hand/{code}?token=<device_token>&last_seq=N`. Сообщение: `{"type", "seq", "ts", "payload"}`. При переподключении сервер досылает пропущенные события по `last_seq`.

**Сервер → Стол (публично):** `lobby.updated`, `settings.vote`, `oath.updated`, `scene.opened`, `narration.public`, `turn.status`, `round.resolving`, `roll.public`, `clocks.updated` (с учётом стадии показа), `map.updated`, `combat.state`, `cutscene.play`, `save.indicator`, `session.paused`, `reader.assigned`.

**Сервер → Рука (только своему герою):** `hero.state`, `view.updated`, `feed.message`, `tasks.updated`, `facts.updated`, `chips.updated`, `action.recognized`, `consent.request`, `consent.result`, `reaction.request` (Защититься или Контратаковать), `roll.prompt`, `hear.update` (кто тебя слышит), `reader.block`, `notes.private`, `dying.state`, `secret.revealed`, `vote.request`, `map.personal`.

**Рука → Сервер:** `join`, `claim_hero`, `ready`, `setting.propose`, `setting.vote`, `oath.progress`, `oath.complete`, `action.submit_text`, `action.confirm`, `action.cancel`, `combat.choose` (`category`, `variant`, `target`), `reaction.choose`, `consent.respond`, `turn.end`, `turn.unend`, `whisper.send`, `shout.send`, `fact.share`, `item.use`, `item.give`, `item.stash`, `move.step`, `heal.self`, `rescue.do`, `interrogate.choose`, `captive.fate`, `growth.choose`, `note.save`, `vote.cast`, `cutscene.skip`, `save.exit_request`, `leave`.

**Правила доставки:**
- Каждое событие формируется отдельно для каждого получателя функцией, которая проходит `visible_facts`, видимость часов и состояния локаций. Нельзя рассылать общий слепок состояния всем.
- Клиент при расхождении запрашивает полный снимок своего представления (`hero.state` + `facts.updated`), а не восстанавливает сам.

## 6. Интеграция с ИИ

1. **Контекст интерпретатора** строится только из знаний героя: известные зоны (с `zone_aliases`), известные задачи, видимые враги и объекты местности, предметы, способности, положение других героев (только публично видимое). Скрытая правда в контекст не попадает.
2. **Выход интерпретатора** валидируется Pydantic-схемой (`app/ai/schemas.py`) и проверкой по контексту (все `id` существуют, зоны достижимы, согласия по правилам). Сложность считается `rules.compute_difficulty` плюс условия мира. Игрок видит карточку «Я понял так» и подтверждает.
3. **Диктор** получает результат движка (исход, `effects`, `revealed`, `clocks_changed`, профиль героя, `scene_facts`, `enemy_facts`, жестокость). Скрытая правда не передаётся.
4. **Устойчивость:** таймаут 12 с, до 3 повторов с добавленной ошибкой валидации, затем запасной режим: интерпретатор просит игрока выбрать из знакомых ему действий, диктор берёт заготовленный шаблон из `data/fallback_narration/`. Игра не должна останавливаться.
5. **Журнал:** каждый запрос и ответ ИИ пишется в журнал (с усечением). Ключ API берётся из `.env`, в клиенты не попадает.
6. **Метрики:** время ответа, число повторов, доля запасных ответов. Показывать в `GET /api/dev/ai-stats` при `DEV=1`.

## 7. Сценарии как данные
Формат: `data/scenarios/ship_without_crew.yaml` (образец, проходит `tests/test_scenarios.py`). Загрузчик сценария обязан отвергнуть файл, если нарушены проверки из этих тестов (несимметричная смежность, подсказка уровня 1–2 называет секрет, число врагов зависит от игроков, ссылка на несуществующую зону или часы). Сюжетные тексты кат-сцен лежат в `offline_assets_plan.md`, файлы озвучки в `assets/audio/cutscenes/{id}.mp3`.

## 8. Сохранения
Снимок `snapshot_json` хранит состояние сессии, героев, ранения, мир, факты (`known_by`), часы, «книгу саги», привязки игроков. Журнал событий хранится вместе с позицией `event_log_cursor`. Загрузка воссоздаёт состояние бит в бит: тест круглого пути обязателен (раздел TEST_PLAN, P-xx). В снимке `save_version`; при несовпадении версий запускается миграция или загрузка отклоняется с понятным сообщением.

## 9. Фронтенд

**Стол (16:9):** большая карта фокуса (SVG, около 65%), правая колонка с обзорной картой и часами, нижний ряд из 4 плиток, строка субтитров, верхняя панель (раунд, Чтец, «Общая карта», «Настройки», значок сохранения), баннер «Отряд разделён», статусы игроков, оверлей кат-сцены, анимация кубика. Подписей зон на картах нет, имя зоны появляется после посещения.

**Рука (портрет):** шапка (портрет, Стойкость ячейками, Судьба, значки приёмов, статус хода, индикатор сохранения) и вкладки: **Локация** (карточка «Вид», лента сообщений, известные задачи, подсказки, ввод, «Шепнуть», «Окрикнуть», «Закончить ход», переключатель «Зоны / Мир»), **Рюкзак**, **Моя сага**, **Тело** (силуэт, лечение). Блок «Читай вслух» у Чтеца. Окно «Защититься или Контратаковать» при ударе по герою.

**Ассеты:** любой отсутствующий файл заменяется запасным значком или текстом. Звук запускается кнопкой «Включить звук» (ограничение браузера). Прототип визуала: `docs/gemini_html_prompt_v3.md` с обновлениями из `rules_update_v6.md` и `combat_v8.md`.

## 10. Нефункциональные требования
- **Задержка:** событие от нажатия до обновления других экранов меньше 300 мс в локальной сети (без ИИ). Ответ ИИ не блокирует остальных игроков: пока идёт разбор, экран показывает «Диктор думает».
- **10 игроков** одновременно без деградации (нагрузочный тест в плане).
- **Безопасность:** код приглашения 8 символов, токены устройств, токен Стола показывается только хосту. Сервер отвергает подмену `hero_id`. Никаких секретов героя в публичных каналах.
- **Конфигурация (`.env`):** `GEMINI_API_KEY`, `MODEL_INTERPRETER`, `MODEL_NARRATOR`, `AI_TIMEOUT_S`, `HOST`, `PORT`, `DEV`, `DICE_SEED`.
- **Журналы:** структурные, с `session_id` и `seq`.

## 12. Определение готовности MVP
Все тесты уровня P0 из `TEST_PLAN.md` зелёные; вечер на 2 и на 6 игроков сыгран без остановок; все три угрозы сцены имеют все исходы; нет утечек скрытой информации в сетевых сообщениях (проверка автоматическим тестом); при отключении Gemini игра продолжается в запасном режиме; сохранение и загрузка возвращают состояние без отличий.
